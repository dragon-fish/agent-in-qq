# Codex 回合内插话

## 目标

Agent in QQ 的 Codex 回合运行时，后续消息可以在 Codex 允许的边界加入当前回合。

## 决定

- 对运行中的普通回合按入队顺序调用 `turn/steer` 并指定当前回合 ID。空闲时用 `turn/start`。独立的压缩命令按队列顺序运行。
- 用客户端消息 ID 关联回合内插话。Codex 发出对应的用户消息事件时，桥接才从队列取走该消息、登记本轮的发言来源，并在该处收束 QQ 流式回复。
- 到回合结束时仍未被 Codex 取走的消息留在队列，由后续回合处理。先收到的消息排在前面，已经被当前回合取走的消息只结算一次。

## 验收

- 在 Codex 执行工具期间发送消息，下一次模型调用收到插话，QQ 回复按实际接收位置分段，回合 ID 保持一致。
- 连续插话按发送顺序交给 Codex。回合结束与插话相撞时，未被取走的消息按原顺序在下一轮处理。
- 验证压缩和 Claude Code 的既有队列行为，并用隔离的 App Server 检查协议交互。
