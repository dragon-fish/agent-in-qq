# agent-in-qq 支持 Claude Code 和 Codex

## 目标

用一份代码维护 QQ 接入。一个 QQ 官方 bot 连接 Claude Code，另一个连接 Codex，两边同时运行，并可独立重启和部署。

## 范围

- 首版支持一个 Claude Code bot 与一个 Codex bot 同时运行。
- Codex 复用私聊、群聊触发与历史、媒体收发、私聊流式回复、审批按钮和现有 QQ 工具。支持新建会话、自动续聊、停止当前轮次和切换工作目录。
- 现有 Claude bot 的配置与会话仍可读取。项目文档使用 `agent-in-qq` 名称。
- 同类型实例并行、跨后端会话迁移、在线切换后端和集中管理多个服务留待后续。

## 决定

1. **一个 bot 一个服务。** 每个进程启动时通过 `QQ_AGENT_BACKEND` 选择 `claude` 或 `codex`，默认 `claude`。Codex 必须提供独立的 `QQ_STATE_DIR`，使用自己的 QQ AppID 和 AppSecret。配对权限、会话映射、群历史和日志按状态目录存放。两个进程分别注册服务和检查存活，`/restart` 只重启收到命令的 bot。有自动回滚的服务使用各自的部署 checkout，以免一个实例切换另一实例的代码版本。
2. **共用 QQ 行为。** 两个后端通过同一套消息路由、排队、回复渲染和按钮处理接入 QQ。适配器负责会话操作、协议事件与工具注册。Claude 沿用 Agent SDK，Codex 通过 stdio 连接本地 App Server。Codex 使用 App Server 的双向请求来接收审批和问题，并把决定回传给正在等待的轮次。
3. **每个 QQ 对话有自己的 Codex thread。** 私聊和每个群分别记录 thread ID。新对话创建 thread，后续轮次和服务重启按保存的 ID 继续。用 App Server 的文本增量驱动现有私聊流式发送，群聊沿用现有分段发送。停止命令中断当前轮次。
4. **按后端解释权限。** Codex 分别配置沙箱和审批策略。待审批操作复用 QQ 按钮及现有身份校验，群聊发起的审批仍由主人在私聊处理。QQ 工具沿用现有参数、可见范围和响应逻辑。

## 验收

- 用原有 Claude 配置启动，并从已有会话续聊。
- 让两个 QQ bot 同时收发私聊和群聊。重启其中一个服务后，另一个的进行中任务继续完成，重启的 bot 按已保存 ID 续聊。
- 验证 Codex 私聊逐步显示文本、能发回媒体，能在 QQ 允许和拒绝待审批操作，能停止当前轮次。用群 @ 和昵称触发群会话，并验证群历史工具和审批回到主人私聊。
- 在启用真实 QQ bot 前，用定向协议检查验证 Codex thread 恢复、审批回包、取消和 QQ 工具调用。
